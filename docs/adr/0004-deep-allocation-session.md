# Keep active allocation behind a deep Session screen

The setup-only `Home` screen owns the platform-specific preparation policy, editable Team count, optional Player selection, and Pairing Mode, then mounts an allocation-specific Session module with an immutable snapshot of that configuration. Android always snapshots an Observed Player Count, while iOS and web may snapshot either an Observed Player Count or a Declared Player Count. The Session converts a Declared Player Count into its assignment plan and continues to own touch lifecycle, Round progression, result snapshots, and safe exit. We rejected letting `Home` coordinate planning because it would duplicate Single- and Multi-Round rules across UI and reducer code; we also rejected a generic game engine because no second game has demonstrated a shared interface. Internal lifecycle and Round-navigation seams keep deterministic tests and platform adapters local without expanding the Session's external interface. Lifecycle transitions emit declarative effects through one internal seam: the production adapter owns Reanimated countdowns, thread crossings, capacity feedback, and feedback scheduling, while deterministic tests use a fake clock and recording adapter against the same effect stream.
